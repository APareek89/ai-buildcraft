How a reward number becomes a weight update

A reward model outputs one number. Weights change by backpropagation, which needs a differentiable path. The text was sampled, and sampling has no derivative. So where is the path? This page answers that with numbers you can change.

The answer in one sentence. The reward never receives a gradient. It acts as a multiplier on a gradient that comes entirely from log π(y|x), the log-probability the policy assigned to the tokens it already produced. You never differentiate the reward, and you never differentiate the sampling.

Where the gradient does and does not flow

The thing that trips people up: you generate the text once without gradients, then run the model again over those same tokens with gradients on. Step 4 is not a second generation. It is a forward pass over a fixed sequence, purely to obtain a differentiable log π.

Why a loss at all, when we want to maximise reward?

Because optimisers minimise. The quantity you actually want to maximise is expected reward. The score-function identity, also called REINFORCE, says its gradient can be written as:

∇θ E[R] = E[ R · ∇θ log πθ(y) ]

Read where the ∇ sits. It is applied only to log π. R is outside it. So if you define a loss whose gradient equals that expression, an ordinary optimiser does the right thing:

L = − R · log πθ(y)

Minimising this maximises reward-weighted log-probability. That is the entire bridge.

What to notice


    

  • Set R = 0. Every gradient becomes zero. No reward, no learning signal, regardless of how confident the policy was.
    • 

  • Set R = −1. Every sign flips. The sampled token is now pushed down.
    • 

  • Change R from 1 to 2. The gradients double exactly. R scales, it never redirects.
    • 

  • Raise the sampled token's logit until its probability is near 1. Its gradient shrinks toward zero. A policy already certain has little left to learn from being told it was right.

Why raw REINFORCE is unusable, and what PPO bolts on



Problem 1 · variance, fixed by a baseline


The gradient depends on which token happened to be sampled. Over a large vocabulary that estimate swings violently. The fix is to subtract a baseline b and use the advantage A = R − b.


It is provably unbiased because the baseline does not depend on the action sampled. The intuition shifts from "was this good" to "was this better than usual for this prompt". In PPO that baseline is produced by a learned value model, which is a third network in memory.



Problem 2 · reusing samples, fixed by a ratio


Generation is the slow part, so you want several gradient steps per batch. After step one the policy has moved, so the samples came from an old policy. Correct for it by importance sampling:


r(θ)  =  πnew(y) / πold(y)



Problem 3 · the ratio explodes, fixed by clipping


This is all PPO really is:


LPPO  =  − min( r·A ,  clip(r, 1−ε, 1+ε)·A )

The clip is deliberately one-sided. With a positive advantage it caps the gain, so one lucky sample cannot run away with the policy. With a negative advantage it keeps pushing down hard, because a response the policy has drifted toward that scores badly should be suppressed without a ceiling. Set A to −1 and slide the ratio past 1+ε to see it.



Problem 4 · reward hacking, fixed by a KL penalty


A policy optimising a reward model will find its blind spots and produce output that scores brilliantly and is useless. So the reward gets a penalty for drifting from the frozen reference model:


Rfinal  =  R(x,y)  −  β · KL( πθ ‖ πref )


That β is the same β as in DPO. DPO folds this leash algebraically into its loss rather than applying it as a separate penalty. Recognising that the two are the same quantity is a good interview answer.



Where the reward model itself comes from


It never sees a score. Humans are unreliable at absolute ratings and reliable at comparisons, so the training data is pairs, and the loss only cares about the difference:


LRM  =  − log σ( r(x, ychosen) − r(x, yrejected) )

Because only differences matter, the absolute scale of the reward is arbitrary. That is why a baseline is not optional: without it, the numbers fed into the policy gradient have no meaningful zero.


The ceiling nobody mentions. The reward model's ranking accuracy caps everything downstream. At 60% accuracy it emits near-noise, and no amount of PPO tuning will rescue the policy. Check that number first when an RLHF run disappoints.



GRPO, and why PPO is fading


PPO holds four models in memory: policy, reference, reward model, value model. On a large model that is brutal. GRPO deletes the value model. Instead of learning a baseline, sample several responses to the same prompt and use the group's own mean as the baseline:


Ai  =  ( Ri − mean(Rgroup) ) / std(Rgroup)


Legitimate for exactly the reason given earlier: any baseline independent of the sampled action leaves the estimator unbiased, and a group mean qualifies. By construction roughly half the group gets a positive advantage and half negative.

Rearranged, the reward model cancels out and you are left with a supervised-looking classification loss over preference pairs. No sampling, no reward model, no value model, no clipping. For a grounded product assistant that is the right tool, which is why notebook 06 used it.



Six things to be able to say


    

  • Where the gradient comes from. The reward is a scalar multiplier on ∇log π. Sampling is never differentiated; log-probs are recomputed afterwards on tokens already produced.
    • 

  • Why a baseline exists. Variance reduction, and it is unbiased because it does not depend on the sampled action.
    • 

  • What clipping does, and that it is one-sided on purpose.
    • 

  • What β controls, and that DPO's β is the same leash.

  • Why the reward model's accuracy is the ceiling on everything downstream.
