DBSCAN and HDBSCAN

1. The one-sentence version

DBSCAN and HDBSCAN converts a particular structural assumption into a practical prediction or representation.

2. The intuition

Think of dbscan and hdbscan as a compact rule for deciding which observations should influence one another; the rule helps only when that notion of relatedness matches the problem.

A five-item example

With min_samples=3, five points on a chain can form one cluster if each core neighbourhood overlaps the next—even when the endpoints are far apart.

3. The maths in plain English

\[N_\varepsilon(x)=\{z:d(x,z)\le\varepsilon\},\quad |N_\varepsilon(x)|\ge m\]

Nε is the eps-neighbourhood. A core point has at least m members; overlapping core neighbourhoods create a density-connected cluster.

4. What the model is actually doing during training

  1. Count neighbours inside eps for every point.
  2. Mark points with at least min_samples as core.
  3. Connect density-reachable core neighbourhoods.
  4. Attach reachable border points and label the rest -1 as noise.

6. Assumptions and failure modes

A single DBSCAN eps cannot simultaneously describe a very dense cluster and a diffuse one.

8. Where it's actually used

  • Finding GPS stop regions with stray measurements.
  • Discovering spatial cell populations.
  • Grouping recurring machine states while rejecting transients.
  • Exploratory anomaly/noise separation.

9. How it relates to its neighbours

k-means assumes centroid-shaped groups. HDBSCAN builds a hierarchy over density levels. OPTICS exposes reachability across many eps choices.
