import os
import time
import requests

# --- 1. Authenticate ---
API_TOKEN = os.environ["APIFY_API_TOKEN"]  # never hard-code this
BASE_URL  = "https://api.apify.com/v2"

# --- 2. Trigger the LinkedIn Profile Scraper Actor ---
ACTOR_ID = "2SyF0bVxmgGr8IVCZ"  # Apify's LinkedIn Profile Scraper

payload = {
    "profileUrls": [
        "https://www.linkedin.com/in/satya-nadella/",
        "https://www.linkedin.com/in/marc-benioff/"
    ],
    "proxy": {"useApifyProxy": True}
}

run_resp = requests.post(
    f"{BASE_URL}/acts/{ACTOR_ID}/runs",
    params={"token": API_TOKEN},
    json=payload
)
run_resp.raise_for_status()
run_id = run_resp.json()["data"]["id"]
print(f"Run started: {run_id}")

# --- 3. Wait for the run to finish ---
while True:
    status_resp = requests.get(
        f"{BASE_URL}/actor-runs/{run_id}",
        params={"token": API_TOKEN}
    )
    status = status_resp.json()["data"]["status"]
    print(f"Status: {status}")
    if status == "SUCCEEDED":
        break
    if status in ("FAILED", "ABORTED", "TIMED-OUT"):
        raise RuntimeError(f"Actor run failed with status: {status}")
    time.sleep(15)  # poll every 15 seconds

# --- 4. Fetch the Dataset ---
dataset_id = status_resp.json()["data"]["defaultDatasetId"]
items_resp  = requests.get(
    f"{BASE_URL}/datasets/{dataset_id}/items",
    params={"token": API_TOKEN, "format": "json"}
)
items_resp.raise_for_status()
items = items_resp.json()  # list of lead record dicts

# --- 5. Inspect the first record ---
print(f"Total records: {len(items)}")
print(items[0])  # full JSON for one LinkedIn profile

Common failure modes

  • Empty Dataset (most common): LinkedIn rate-limited the Actor mid-run. Check: len(items) == 0 after a SUCCEEDED status.
  • Partial results: Run succeeded. Only 40 of 200 profiles returned. Check: len(items) < len(input_urls) — always compare counts.

  • Missing fields (non-obvious): A profile is private. The Actor returns a record with null fields. Check: items[0].get('fullName') is not None before passing downstream.

Safe re-run strategy

Wait at least 60 seconds before re-triggering after a rate-limit failure. Use exponential backoff. Double the wait on each retry. 60s → 120s → 240s.

From Raw Apify JSON to a Clean LeadRecord

from dataclasses import dataclass, field
from typing import Optional, Set

# --- 1. Define the LeadRecord dataclass ---
@dataclass
class LeadRecord:
    name: str = ""
    headline: str = ""
    company: str = ""
    employee_count: Optional[int] = None
    linkedin_url: str = ""
    location: str = ""

# --- 2. Helper: safely cast to int ---
def _safe_int(value) -> Optional[int]:
    try:
        return int(value)
    except (TypeError, ValueError):
        return None

# --- 3. Mapper: raw Apify dict → LeadRecord ---
def map_to_lead_record(raw: dict) -> LeadRecord:
    company_details = raw.get("companyDetails") or {}
    return LeadRecord(
        name=raw.get("fullName", "").strip(),
        headline=raw.get("headline", "").strip(),
        company=company_details.get("name", "").strip(),
        employee_count=_safe_int(company_details.get("size")),
        linkedin_url=raw.get("profileUrl", "").strip(),
        location=raw.get("location", "").strip(),
    )

# --- 4. Deduplication: skip already-seen URLs ---
def deduplicate(records: list[LeadRecord]) -> list[LeadRecord]:
    seen_urls: Set[str] = set()
    unique = []
    for rec in records:
        if rec.linkedin_url and rec.linkedin_url not in seen_urls:
            seen_urls.add(rec.linkedin_url)
            unique.append(rec)
    return unique

# --- 5. Full pipeline: list of raw dicts → clean LeadRecords ---
def clean_apify_batch(raw_records: list[dict]) -> list[LeadRecord]:
    mapped = [map_to_lead_record(r) for r in raw_records]
    return deduplicate(mapped)

# --- Usage ---
raw_batch = [
    {"fullName": "Sarah Chen", "headline": "VP Sales",
     "companyDetails": {"name": "Acme", "size": "200"},
     "profileUrl": "https://linkedin.com/in/schen"},
    {"fullName": "Sarah Chen",  # duplicate
     "profileUrl": "https://linkedin.com/in/schen"},
]
clean = clean_apify_batch(raw_batch)
print(clean)  # One LeadRecord, not two

What a Scoring Agent Is — and Why You Need One

In plain wordsA scoring agent is like a loan officer: it reads an application, checks it against fixed rules, then writes a decision with a reason — so every case is judged the same way.

The problem this solves

You have clean . But which leads matter? Without rules, every rep decides differently.

A scoring agent reads each record and applies your criteria. It returns a plus a written reason — consistently.

The three moving parts

  • — the LLM brain. Reads the lead, calls the scoring tool, writes JSON output.
  • Scoring tool — a Python function. Applies deterministic rules: title match, company size, recency.
  • — human gate. Intercepts borderline scores and asks reps to confirm.

Why hybrid, not pure LLM?

Pure LLM scorers hallucinate reasons. Pure rule engines can't handle messy titles. Hybrid: the tool does math; the LLM explains. You get explainability at scale.

How a Lead Flows Through the Scoring Agent

from langchain_openai import ChatOpenAI
from langchain.agents import AgentExecutor, create_openai_tools_agent
from langchain_core.tools import tool
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from pydantic import BaseModel
import json

# --- 1. Define the LeadRecord schema (from Module 2) ---
class LeadRecord(BaseModel):
    name: str
    title: str
    company: str
    company_size: int          # employee count
    industry: str
    linkedin_url: str

# --- 2. The scoring TOOL — deterministic rules, no LLM ---
@tool
def score_lead_tool(title: str, company_size: int, industry: str) -> dict:
    """Score a lead 0-100 against ICP criteria. Returns score and matched flags."""
    score = 0
    flags = []

    # Title match (VP-level or above)
    vp_keywords = ["vp", "vice president", "head of", "director", "chief", "cro", "cso"]
    if any(kw in title.lower() for kw in vp_keywords):
        score += 40
        flags.append("title_match")

    # Company size (50–500 employees)
    if 50 <= company_size <= 500:
        score += 35
        flags.append("size_match")

    # Industry match (SaaS)
    if "saas" in industry.lower() or "software" in industry.lower():
        score += 25
        flags.append("industry_match")

    return {"score": score, "flags": flags}

# --- 3. ICP-aligned system prompt — forces structured JSON output ---
SYSTEM_PROMPT = """You are a sales signal scoring agent.
For every lead, call score_lead_tool with the lead's title, company_size, and industry.
Then return ONLY valid JSON in this exact shape:
{
  "name": "<lead name>",
  "score": <integer 0-100>,
  "flags": ["<matched criteria>"],
  "reason": "<one sentence explaining the score>",
  "routing": "<outreach | review | discard>"
}
Routing rules: score >= 80 → outreach, 50-79 → review, < 50 → discard.
Never add text outside the JSON block."""

# --- 4. Build the agent ---
llm = ChatOpenAI(model="gpt-4o", temperature=0)

prompt = ChatPromptTemplate.from_messages([
    ("system", SYSTEM_PROMPT),
    MessagesPlaceholder(variable_name="chat_history", optional=True),
    ("human", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

tools = [score_lead_tool]
agent = create_openai_tools_agent(llm, tools, prompt)
agent_executor = AgentExecutor(agent=agent, tools=tools, verbose=True)

# --- 5. Score a lead ---
lead = LeadRecord(
    name="Sarah Chen",
    title="Head of Revenue",
    company="Acme SaaS",
    company_size=120,
    industry="SaaS",
    linkedin_url="https://linkedin.com/in/sarahchen"
)

result = agent_executor.invoke({
    "input": f"Score this lead: {lead.model_dump_json()}"
})

# --- 6. Parse and route ---
try:
    output = json.loads(result["output"])
except json.JSONDecodeError:
    raise ValueError("Agent returned invalid JSON — check system prompt.")

if output["routing"] == "review":
    # TODO: wire in your UserProxyAgent review gate here
    print(f"BORDERLINE — send to rep: {output}")
else:
    print(f"Routed to [{output['routing']}]: {output}")

How This Breaks in Practice

Common failures

  • Agent ignores the tool. It guesses a score from the prompt instead of calling score_lead_tool. Fix: add "You MUST call score_lead_tool" to the system prompt.
  • Hallucinated reasons. The LLM writes a reason that contradicts the tool's flags. Fix: instruct the agent to only explain flags the tool returned.
  • Malformed JSON. The agent adds a preamble like "Here is the JSON:". Fix: temperature=0 + explicit "Never add text outside the JSON block" in the prompt.

Non-obvious failures

  • Score drift.Scores shift if you change the model version mid-pipeline. Pin your model string (e.g. gpt-4o-2024-08-06).
  • Silent discard. A JSON parse error swallows the lead — it's neither scored nor flagged. Always log the raw output before parsing.
  • ICP creep. Reps ask to "just lower the threshold" for a slow week. Track threshold changes — they corrupt your signal history.
Rule of thumb: if the agent's reason mentions a criterion the tool didn't flag, the reason is hallucinated. Reject it.

Run these checks on any AI-generated version of this agent:

  • ✅ Tool is actually called. Check verbose=True output — you should see "Invoking: score_lead_tool" before the final answer.
  • ✅ Score matches the flags. If flags = ["title_match", "size_match"], score must be 75. Recalculate by hand.
  • ✅ Reason only cites returned flags. If the reason mentions "industry match" but industry_match isn't in flags, it's hallucinated.
  • ✅ Output is valid JSON. Run json.loads(result["output"]) — if it raises, the prompt needs tightening.
  • ✅ Routing matches the score. Score 87 must route to "outreach", not "review". Check all three threshold bands.

From raw signals to one ranked number

In plain wordsRanking leads by a composite score is like judging a job application: you weigh skills, experience, and culture fit separately, then add them up into one hiring decision.

In module 3 your scoring agent produced individual — one per dimension. Raw scores alone don't show who to call first.

You need three things: a weighted composite score, a to keep fresh signals visible, and a Hot/Warm/Cold tier for clear action.

The three moving parts

  • Weights — each signal gets a share of 100 (e.g. job title = 40, company size = 30, activity = 30).
  • Decay multiplier — a number between 0 and 1 that shrinks older scores.
  • Tier thresholds — cut-offs that map final score to Hot, Warm, or Cold.

Why recency decay?

A lead posting 90 days ago is less urgent than one posting yesterday. lowers older scores so fresh leads surface first.

Why score-drift checks?

An agent can score high but write contradictory reasoning. checks catch mismatches before output ships to reps.

How recency decay shrinks a score over time

Decay formula: multiplier = e^(−0.01 × days). Drag to see how age erodes a raw score of 80.

You have three . Weights: title fit = 40 pts, company size = 30 pts, recent activity = 30 pts.

Step 1 — raw composite score

  • Alice: title 38 + size 28 + activity 27 = 93
  • Bob: title 30 + size 20 + activity 10 = 60
  • Carol: title 35 + size 25 + activity 25 = 85

Step 2 — apply recency decay (e^(−0.01 × days))

  • Alice: signal is 5 days old → decay 0.95 → 93 × 0.95 = 88.4
  • Bob: signal is 2 days old → decay 0.98 → 60 × 0.98 = 58.8

# --- Tier thresholds ---
HOT_THRESHOLD  = 75
WARM_THRESHOLD = 40

# --- Weights (must sum to 100) ---
WEIGHTS = {
    "title_fit":    40,
    "company_size": 30,
    "recent_activity": 30,
}

def composite_score(signals: dict) -> float:
    """Weighted sum of individual signal scores (0-100 each)."""
    return sum(signals[k] * (w / 100) for k, w in WEIGHTS.items())

def apply_decay(score: float, days_old: int) -> float:
    """Shrink score by exponential decay based on signal age."""
    # TODO: compute decay_multiplier using math.exp
    decay_multiplier = math.exp(-0.01 * days_old)  # <-- key line
    return round(score * decay_multiplier, 2)

def assign_tier(final_score: float) -> str:
    """Map numeric score to Hot / Warm / Cold."""
    if final_score >= HOT_THRESHOLD:
        return "Hot"
    elif final_score >= WARM_THRESHOLD:
        return "Warm"
    return "Cold"

# --- Score-drift check ---
def drift_check(agent_reasoning: str, final_score: float, tier: str) -> dict:
    """
    Ask an LLM to verify the agent's reasoning matches the numeric score.
    Returns {"ok": bool, "flag": str}.
    """

        "Does the reasoning justify this tier? Reply JSON: "
        '{"ok": true/false, "flag": "reason if not ok else empty"}'
    )
    raw = llm.invoke([HumanMessage(content=prompt)]).content
    return json.loads(raw)

# --- Full pipeline for one lead ---
def rank_lead(lead: dict) -> dict:

        "final_score": final,
        "tier":        tier,
        "drift_ok":    drift["ok"],
        "drift_flag":  drift["flag"],
    }

How this breaks in practice

In plain wordsA silent failure in a pipeline is like a factory conveyor belt that stops mid-line — boxes pile up at one station while the rest of the line runs empty.

Common failures

  • Silent empty output — zero ranked leads, no error. The Apify Dataset was empty (Actor timed out). Assert len(raw_records) > 0 at ingest.
  • Stage crash with no log — unhandled exception kills the script. Fix: wrap each node in try/except. Write errors to state["errors"] before re-raising.
  • Cron fires twice — overlapping runs corrupt output. Use a lock file or Apify's run-deduplication.

Non-obvious failures

  • Score drift undetected — scores shift week-over-week silently. The pipeline runs cleanly. Log score distribution (min, max, mean) every run. Alert if mean shifts > 10 points.
  • Stale dataset — cron fires but Apify returns cached data. Pass a fresh run_id as Actor input. Verify dataset timestamp in integrity check.
  • Webhook fires on bad data — integrity check skipped or weak. Reps get junk leads. Treat integrity check as a hard gate. Raise an exception if it fails.

AI can scaffold the graph quickly. Check these before running it in production.

  • Every node writes to state["errors"] on failure — not just the terminal.
  • The integrity check is a hard assert or raise — not a soft print("warning").
  • The log file path is writable in your deployment environment (Apify, cron server, etc.).
  • The cron expression matches your intended timezone — off-by-one-hour bugs are common.
  • The run_id is unique per run — AI often hard-codes a static string.
  • Score distribution is logged — so you can detect across runs.
Use when
Use a system cron job when your pipeline runs on your own server and you want full control over the schedule and environment.
Avoid when
Avoid system cron when you're already running on Apify — managing two schedulers adds confusion and can cause duplicate runs.
Rule of thumb
If your Actor lives on Apify, use Apify's built-in scheduler. If you run locally or on your own server, use cron.
