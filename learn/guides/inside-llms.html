LLM-01

Attention recap in one formula

Everything we discussed so far, in maths. x is one token's 384-number vector.

q_i = W_Q x_i k_j = W_K x_j v_j = W_V x_j score(i, j) = q_i · k_j / √d = x_iᵀ (W_Qᵀ W_K) x_j / √d ← W_Q, W_K only appear as one product α_i = softmax over j ≤ i of score(i, j) ← causal mask (tril) out_i = Σ_j α_ij · v_j ← V goes straight to the output y_i = W_O · concat(heads) ← O mixes the heads
  • LoRA on Q and V: Q steers the scores (shared with K). V changes the content directly.
  • KV cache: row i needs one query (q_i) but every key and value (k_1…k_i). Rows are used once; columns are read forever. So cache K and V, never Q.
  • GQA: many query heads share fewer K/V heads. Head size stays the same, so the dot product still works.

LLM-03

RMSNorm

LayerNorm(x) = (x − mean(x)) / std(x) · g + b RMSNorm(x) = x / √(mean(x²) + ε) · g ← no mean, no shift b

It is applied per token, across its C numbers. It only fixes the scale. The learned weight lets the model choose the scale it wants.

LLM-04

RoPE: position by rotation

Instead of adding a position vector to x, rotate q and k. Split each vector into pairs. Rotate pair i by angle pos × θ_i. Early pairs spin fast, later pairs spin slow.

rotate(q, m) · rotate(k, n) = depends only on q, k and (m − n) So the score sees the DISTANCE between tokens, not their absolute place.
  • Applied to Q and K only, because only the score needs position.
  • With a KV cache, keys are stored already rotated. A new token must use its true position (like start_pos in kv_cache_gqa.py).
  • Real code (Hugging Face) pairs the first half with the second half instead of even/odd. Same maths.
LLM-05

SwiGLU MLP

Karpathy: y = W2 · ReLU(W1 x) 2 matrices, hidden = 4C SwiGLU: y = W_down · ( SiLU(W_gate x) ⊙ (W_up x) ) 3 matrices, hidden ≈ 8/3 · C SiLU(z) = z · sigmoid(z) ⊙ = element-wise multiply

The gate decides, per hidden neuron, how much of up(x) passes. These three names are also LoRA targets. "All-linear" LoRA means q, k, v, o, gate, up, down.

LLM-07

Mixture of Experts (MoE)

Replace the one MLP with E smaller MLPs called experts, plus a router. For each token, the router picks the top k experts. Only those run. Attention stays the same.

router scores s = W_r · x (E numbers per token) pick top-k of s (e.g. k = 2 of E = 8) weights g = softmax(top-k scores) output y = Σ over chosen e of g_e · Expert_e(x)
  • Routing is per token, per layer. One word can use experts 2 and 5 in layer 3, and 1 and 7 in layer 4.
  • Experts do not learn neat topics like "maths" or "French". They split work in ways that are hard to read.
  • Some models add a shared expert that every token always uses, plus many small routed experts (DeepSeek style).

LLM-09

Load balancing the router

Left alone, the router sends most tokens to a few experts. Those get better, so they get picked more. The rest die. An extra loss pushes usage to be even.

f_e = share of tokens sent to expert e P_e = average router probability for expert e aux = E · Σ_e f_e · P_e ← smallest when both are spread evenly loss = lm_loss + 0.01 · aux

Other fixes: a capacity limit per expert (extra tokens are dropped or overflow), and DeepSeek-V3's bias trick that balances without an extra loss.

LLM-10

Quantization: the basic idea

Store each weight in fewer bits. Pick a scale so the biggest weight maps to the biggest integer. Round the rest. At use time, multiply back.

scale = max(|w|) / 127 (int8: −127 … 127) q = round(w / scale) stored as int8 w' = q · scale error = w − w' (rounding only)

Why it is fast, not just small: decoding one token reads every weight from memory. Fewer bytes to read means more tokens per second.

LLM-11

4-bit, groups and outliers

At 4 bits there are only 16 levels. One large weight makes the scale large, and small weights round to zero. Fix: one scale per small group of weights.

FormatBits7B model70B modelNotes
FP323228 GB280 GBTraining master copy
BF16 / FP161614 GB140 GBDefault for serving
FP8 / INT887 GB70 GBNear-lossless
INT4 (GPTQ, AWQ, GGUF Q4)~4.5~4 GB~40 GBSmall quality loss
  • Weight-only (W4A16): weights small, maths still in 16-bit. W8A8: activations also 8-bit, needs hardware support.
  • KV cache quantization: store K and V in 8 or 4 bit. Helps long context.
  • QLoRA: frozen base in 4-bit (NF4), LoRA adapters trained in bf16 (LLM-12).
LLM-12

LoRA in code

y = W x + (α / r) · B A x W: (out, in) frozen A: (r, in) B: (out, r) params trained = r · (in + out) vs in · out (r = 8, 4096×4096 → 65K vs 16.8M)

B starts at zero, so the model starts exactly as the base model. With GQA, k_proj and v_proj are narrower, so their adapters are smaller too.

LLM-13

Sampling: temperature and top-p

p_i = softmax(logits / T) T < 1 sharper, T > 1 flatter, T → 0 = argmax top-p: keep the fewest tokens whose probabilities add up to p, renormalise, sample

Karpathy's generate uses plain torch.multinomial(probs): temperature 1, no top-p.

LLM-14

Speculative decoding

Decoding is slow because each token reads all weights. A small draft model guesses k tokens. The big model checks all k in one pass. Keep the guesses it agrees with.

The output is exactly what the big model would write alone. The sampling version uses an accept/reject rule that keeps the same guarantee.
