SP-01

Audio is just a long list of numbers

A microphone measures air pressure many times per second. Speech models usually use 16,000 samples per second.

SP-02

Mel spectrogram: audio as an image

Cut the wave into short overlapping windows (25 ms, every 10 ms). Find which frequencies are in each window (FFT). Squash frequencies into 80 bands spaced like human hearing (mel). Take the log, because loudness is heard on a log scale.

frames/sec = sr / hop = 16000 / 160 = 100 result = (n_mels, frames) = (80, 100) per second ← a 1-channel image: frequency × time

From here, speech looks like CNN and transformer work: a 2D grid, or a sequence of 80-number frames. Each frame plays the role of a token embedding.

SP-03

Speech-to-text encoder (Whisper style)

Two 1D convs read the mel frames and halve the time steps. Then normal transformer blocks run with no causal mask, because the whole clip is already recorded.

30 s clip → (80, 3000) mel → conv stride 2 → (1500, d) audio tokens
SP-04

Cross-attention: Q from text, K and V from audio

This is the key new piece. The text decoder asks questions (Q). The audio answers (K and V). It is the same maths as self-attention, but Q and K/V come from different sequences.

q_i = W_Q · text_i k_j = W_K · audio_j v_j = W_V · audio_j score is (T_text × T_audio), not square, and no causal mask

KV cache link: the audio K and V never change while decoding, so they are computed once and reused for every text token. Rows (text queries) are new each step; columns (audio keys) stay fixed.

SP-06

CTC: speech-to-text without a decoder

Simpler and faster option. Encoder only. Predict one letter (or "blank") per audio frame, then clean up.

frames: h h _ e _ l l _ l l _ o o merge repeats → h _ e _ l _ l _ o drop blanks → "hello"

The blank lets the model write a double letter ("ll" in hello) and wait on silence. Good for streaming, since each frame is decided as it arrives.

SP-07

Text-to-speech, classic: text → mel → vocoder

Step 1: an acoustic model turns text into a mel spectrogram. Step 2: a vocoder turns mel back into a waveform. The mel threw away phase, so the vocoder must invent it. That is why it is a neural network.

1 mel frame = 160 samples → upsample time by 8 × 4 × 5 = 160 ConvTranspose1d length: L_out = (L − 1)·S − 2P + K

Real vocoders (HiFi-GAN style) add residual blocks and train with a discriminator (GAN loss) plus a mel loss, so the audio sounds crisp, not muffled.

SP-08

Modern TTS: audio tokens + a language model

A neural codec turns audio into discrete tokens, like text tokens. Then a GPT-style model predicts audio tokens from text tokens. The codec decoder turns them back into sound. The codec uses residual vector quantization (RVQ).

codebook 1: nearest match to z → token c1 codebook 2: nearest match to (z − e1) → token c2 each level fixes what is left ... 8 codebooks × 1024 entries → 8 tokens per frame
  • Text → LLM → audio tokens → codec decoder → wave. This is how VALL-E-style and many current voice models work.
  • Speech-to-speech models put text and audio tokens in one transformer, so they can listen and talk without a separate STT and TTS step.
SP-09

Voice agent: where the latency goes

cascade: mic → VAD/endpoint → STT → LLM → TTS → speaker speech LM: mic → one model (audio in, audio out) → speaker
StageWhat slows itMain lever
EndpointingWaiting to be sure the user stoppedBetter turn detection, shorter silence timeout
STTTranscribing after speech endsStreaming STT (CTC or chunked encoder)
LLMTime to first tokenSmaller or faster model, prompt caching, KV cache reuse
TTSTime to first audioStreaming TTS, start speaking on first sentence

Rule of thumb: stream every stage. No stage should wait for the previous one to fully finish.
