Step 1 of 8

Forward pass and loss: five tokens instead of 151,936

The model reads the tokens so far and produces one number per vocabulary token, the logit. Softmax turns the logits into probabilities that sum to one. The loss for this position is the negative log of the probability given to the token that actually came next. A loss of 0.7 means the correct token had about 50% probability; a loss of 2.3 means about 10%.

The gradient with respect to the logits is simply p − onehot(target): the target's entry is negative, everyone else's is positive. The update subtracts the gradient, so the target logit goes up and every other logit goes down. That is the entire mechanism behind the stop-token story: when <|im_end|> was the label, <|endoftext|> was "everyone else" and got pushed down at every answer ending.

Step 2 of 8

The update: how far one weight moves per step

Plain gradient descent moves each weight by learning rate × gradient. AdamW, used in this teaching example, divides the gradient by a running estimate of its own size, so each weight moves by roughly the learning rate itself per step, in the direction the gradient has been pointing. A useful bound follows: after N steps no weight has travelled more than about lr × N. The archived CPT example allowed 5e-5 × 200 = 0.01 per weight; the archived SFT example allowed 1e-4 × 100 = 0.01.

A change of 0.01 in one weight is invisible. In Qwen a logit is a sum over 2048 hidden dimensions and 28 layers, so thousands of tiny coordinated changes add up. The slider for weights per logit imitates that: every one of the k weights receives the same gradient and moves together.

Keep lr at 1e-4 and 100 updates, then raise k to 2048. The same per-weight travel now changes the logits by units, not hundredths. This is why 100 updates were enough to rewrite the answer style of a 1.7 billion parameter model, and why they were nowhere near enough to store thousands of one-off facts: style is a coordinated push in one direction; each fact is its own direction.

Step 3 of 8

LoRA: the update is a product of two thin matrices

A full fine-tune would change every entry of a weight matrix W. LoRA keeps W frozen and adds a correction ΔW = (α / r) · B · A, where A is r × din and B is dout × r. Only A and B train. B starts as zeros, so at step 0 the model is exactly the base. During the forward pass the layer computes W·x + (α/r)·B·(A·x); for inference the two can be merged into one matrix with no extra cost.

The rank r caps how many independent directions the correction can contain. Every row of B·A is a multiple of the same r row-vectors of A. Small r is cheap and hard to overfit; it is also why attention-only, rank-16 adapters reshape style easily but store facts poorly.

Step 4 of 8

CPT vs SFT: the same loss, a different mask

Both stages use exactly the loss and update from steps 1 and 2. The only difference is which positions count. Continued pretraining scores every token of the document. Supervised fine-tuning sets the label to −100 for the system text, the user text and the role headers, so only the assistant's answer and its ending token contribute. The prompt still matters: the answer tokens attend to it, so the adapter learns to use the prompt rather than to predict it.

The loss for one example is the average over scored positions. In your practice data the ending token is one of about 40 scored tokens per answer, so it carries about 2% of the signal.

In the Base weights the <|im_end|> row is an untrained placeholder identical to 93 other rows, and the adapter never touches embedding rows. Training toward it lowered <|endoftext|> without making <|im_end|> reachable. Example B switched the ending to the token the Base already knows, and the loop disappeared.

Step 5 of 8

Batches, accumulation and clipping

One update in the archived example sees four examples: micro-batch size 1, accumulated four times. The gradients are added before the optimizer step, so accumulation is a way to get a larger batch with the memory of a small one. The example weights each micro-batch by its share of scored tokens, so a 200-token answer and a 40-token answer contribute per token, not per example.

Gradient clipping measures the length of the whole gradient vector and, if it exceeds 1.0, scales every entry down by the same factor. Your CPT gradients had norms around 0.4 to 1.1 and were mostly untouched. Your SFT gradients had norms of 3 to 4.5 at every step, so every update was scaled to roughly a third before AdamW saw it. With AdamW the effect is mild, because the optimizer normalises by gradient size anyway.

Step 6 of 8

Learning-rate schedule: warm up, then cool down

The learning rate is not constant. A short warmup lets AdamW's running estimates settle before full-size steps; then the rate decays so the last updates make small corrections instead of overshooting. The example uses a straight-line decay to zero; the command-line trainer uses a cosine curve. Archived SFT example: peak 1e-4, warmup 2 updates, 100 updates, ending at about 1e-6.

Step 7 of 8

Decoding: how an answer ends

Inference repeats one forward pass per token. The model outputs probabilities for the next token; a decoding rule picks one; the pick is appended and the loop continues until a stop token is produced or max_new_tokens is reached. Greedy decoding always takes the highest probability. Sampling draws in proportion to the probabilities after dividing the logits by a temperature: below 1 sharpens, above 1 flattens. Neither rule can produce a stop token the model has not learned to make likely.

min_new_tokens exists, and it works by forbidding the stop token for the first N picks. The panel shows what that does: the mass moves to the second-best token, which is how a model that wanted to stop restarts its sentence instead.
